# Страница партнёра в админке

При клике на строку партнёра в «Партнёры» открывается отдельная страница `/admin/partners/:id` (только главный администратор, как и список).

## Что на странице

**Шапка**
- Имя, телефон, email, статус (вкл/выкл — переключатель), дата подключения.
- Ссылка `/r/КОД` с копированием, старые коды партнёра.
- Скидка клиентам (0–20%) и «Не предлагать консультацию врача» — можно править прямо здесь.
- Кнопка «Открыть кабинет партнёра» (режим просмотра).

**Сводка (карточки)**
- Клиентов закреплено, оплаченных заказов, оборот клиентов, начислено всего, выплачено, к выплате (+ кнопка «Выплачено»).

**Вкладка «Клиенты»**
- Все закреплённые клиенты, сгруппированные в одного человека (аккаунт + его телефон + email).
- Колонки: клиент (ФИО, если есть аккаунт или заказ), телефон, email, есть ли аккаунт, дата закрепления, число заказов, сумма оплат, начислено партнёру.
- Действия: открыть карточку пациента (если есть аккаунт), перезакрепить за другим партнёром, открепить.
- Поиск по имени/телефону/email.

**Вкладка «Заказы»**
- Все заказы с этим партнёром — чекапы и подписки, включая неоплаченные.
- Колонки: дата, № заказа, тип (Чекап / Подписка) и что куплено, клиент, сумма до скидки, скидка, оплачено, статус (Оплачен / Ожидает оплаты / Отменён / Тест), комиссия партнёра.
- Фильтры: тип, статус, период; итоги внизу по отфильтрованному.
- Тестовые заказы помечены и не входят в начисления.

**Вкладка «Выплаты»**
- История выплат: дата, сумма, кто отметил, комментарий; добавить выплату с произвольной суммой и комментарием; итог «Начислено − Выплачено = К выплате».

## Что меняется в списке «Партнёры»
- Строка кликабельна (имя — ссылка), кнопки копирования/переключателя не открывают страницу.

## Технические детали
- Новый маршрут в `App.tsx` под `SuperAdminRoute`, страница `src/pages/admin/AdminPartnerDetail.tsx`, данные через хук `useAdminPartnerDetail`.
- Источники: `partners`, `partner_codes`, `partner_clients`, `energy_orders` и `payment_orders` по `partner_id` (все статусы), `partner_payouts`, `profiles`, `subscription_plans` для названия тарифа.
- Склейка клиентов: `partner_clients` kind=user → profile (phone/email); phone/email без аккаунта — отдельные записи, если совпадают с профилем — присоединяются к нему; заказы сопоставляются по user_id, затем нормализованному телефону/email.
- Правка скидки/флага — существующий `partner_update_settings(p_user_id)`; выплаты — insert в `partner_payouts` с `note`.
- Если RLS не даёт суперадмину читать неоплаченные заказы — проверить политики и при необходимости добавить SELECT для superadmin.
