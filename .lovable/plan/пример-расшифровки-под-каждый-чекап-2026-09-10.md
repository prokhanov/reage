# Пример расшифровки под каждый чекап

Сейчас кнопка «Посмотреть пример расшифровки» в блоке «Пример результата» ничего не открывает (в `EnergyExpertResult.tsx` у неё нет обработчика). Сделаем так, чтобы по клику поверх страницы открывался пример отчёта — свой для каждого чекапа, только с теми показателями, которые в него входят.

## Как это будет выглядеть

Клик по кнопке открывает окно поверх страницы (как пример отчёта на главной), с прокруткой и закрытием по крестику или Esc. Внутри — отчёт по образцу больших отчётов ReAge, но короче:

1. **Шапка и резюме.** Имя и возраст условного пациента (например «Елена, 38 лет»), название чекапа, дата. Дальше короткое вступление: панель в целом выглядит хорошо, но есть один показатель, на который стоит обратить внимание.
2. **Показатели.** Все биомаркеры чекапа, каждый — отдельной карточкой в рамке с фоном по статусу: название и код, значение, шкала ReAge (та же, что в отчётах и в блоке «Пример результата»), затем «Что это значит» — что показывает маркер, и для отклонения — «Как это может ощущаться» и подробный разбор.
3. **Рекомендации.** Короткий блок с конкретными шагами по найденному отклонению и сроком контрольной пересдачи. Если в чекапе всё в норме — блок про поддержание.

Внизу окна — кнопка «Добавить в корзину», чтобы из примера можно было сразу оформить заказ.

## Сценарий примера

Для каждого чекапа — один показатель с отклонением (по сюжету, логичному для этого чекапа: у «Энергии» — низкий ферритин, у «Щитовидной железы» — пограничный ТТГ и т. д.), остальные в норме или в допустимом диапазоне. Тексты пишутся в стиле существующих отчётов ReAge: спокойный врачебный нарратив, без списков-перечислений внутри разбора.

## Техническая часть

- Новый файл `src/data/checkupExampleReports.ts`: для каждого slug из `CHECKUPS` — объект `{ patient: { name, age, gender }, intro, markers: [{ code, value, unitOverride?, meaning, feeling?, commentary? }], recommendations: [...] }`. Коды биомаркеров берутся из справочника `biomarkers` (например `FERR`, `25-OH D`, `TSH`, `HbA1c`).
- Референсные диапазоны не дублируем: подтягиваем строки из таблицы `biomarkers` по кодам одним клиентским запросом (тот же подход, что в `src/hooks/useBiomarkerNames.ts`), с кэшем на модуль. Если код не найден — карточка не рендерится.
- Новый компонент `src/components/landing/energy/CheckupExampleReport.tsx`: `Dialog` из ui-kit, содержимое рендерится из данных выше. Карточка показателя переиспользует `BiomarkerScale` и `getBiomarkerStatus` из `@/lib/biomarkerNorms` — те же 7-сегментные статусы и токены `status-*`, что и в `EnergyExpertResult.tsx`.
- `EnergyExpertResult.tsx` получает текущий чекап (через `useEnergyOrder()`, как остальные блоки страницы) и вешает на кнопку открытие диалога. Больше ничего в блоке не меняем.
- Цель по корзине из диалога — `addToCart()` из `EnergyOrderContext`.
- Метрика: цель `<slug>_example_report_open` через `reachGoal`.

## Объём текстов

Тексты разбора нужно написать под 12 чекапов; всего порядка 90 карточек показателей. Пишем компактно: для нормальных показателей — 2–3 предложения «что это значит», для отклонения — развёрнутый абзац с ощущениями и следующим шагом.
