# Корзина с несколькими чекапами

Сейчас корзина живёт внутри страницы одного чекапа: при переходе на другой чекап всё, что было добавлено, пропадает. Сделаем общую корзину для всего сайта: в неё можно положить несколько чекапов, она сохраняется при переходах между страницами и после перезагрузки, а оплата проходит одним платежом на всю сумму.

## Что увидит пользователь

- Кнопка «Добавить в корзину» на любой странице чекапа добавляет его к уже собранному заказу.
- Счётчик в шапке и нижняя кнопка на телефоне показывают общее количество чекапов.
- Если чекап уже в корзине, кнопка показывает «В корзине · Оформить» и просто открывает панель.
- В панели заказа — список всех добавленных чекапов с ценой и крестиком «удалить»; пустая корзина показывает подсказку.
- Одна клиника, один email/телефон, один промокод и одно согласие на весь заказ.
- Консультация врача — одна на заказ, +3 500 ₽ (не умножается на число чекапов).
- Промокод даёт скидку на сумму всех чекапов (консультация без скидки), как и сейчас.
- Итог считается по всем позициям; кнопка оплаты неактивна, если корзина пуста.
- Корзина хранится в браузере и очищается после успешной оплаты.

## Технические детали

- `EnergyOrderContext` выносится из страницы в глобальный провайдер (обёртка в `App.tsx`), состояние — массив slug'ов + выбранная клиника, с сохранением в `localStorage` и синхронизацией между вкладками. API: `items`, `addItem(slug)`, `removeItem(slug)`, `clear()`, `hasItem(slug)`, `count`.
- `Checkup.tsx` перестаёт создавать свой провайдер; текущий чекап страницы передаётся отдельно (пропом/хуком), `cartCount` берётся из корзины.
- `EnergyCart.tsx`: шаг 1 рендерит список позиций вместо одной; расчёт скидки и итога по сумме `items`.
- Серверная `energy-create-payment` принимает `bundles: string[]` (совместимо со старым `bundle`): валидирует каждый slug по серверному каталогу, считает сумму цен, формирует чек Робокассы с отдельной позицией на каждый чекап + консультация.
- В `energy_orders` колонка `bundle` остаётся источником совместимости — пишем первый slug; полный список сохраняем в новую колонку `bundles` (text[]/jsonb, миграция + GRANT по существующему шаблону).
- `robokassa-result`: уведомление в Telegram перечисляет все чекапы заказа.
- Аналитика: `checkup_payment_click` отправляется один раз на заказ, персональная цель `<slug>_payment_click` — по каждому чекапу в корзине; на странице возврата `paid`/`failed` так же по всем slug'ам заказа + общая цель один раз.
- `EnergyPaymentResult.tsx` показывает список оплаченных чекапов, кнопка возврата ведёт на первый из них.
