# Отдельный тип отчёта «Организм в целом»

## Что мы сделали для отчёта Алёны (27.09)

Отчёт собирали вручную, по шагам:

1. **Генерация.** Запустили обычную генерацию по каждой системе, затем ИИ склеил всё в один раздел «Организм в целом»: вступление, разбор всех 17 показателей по логике (железо, ферритин, гемоглобин, кровь, витамины, минералы, тромбоциты, лейкоциты), «Сильные стороны», «Зоны внимания».
2. **Промпты.** Основой взяли системные промпты и общие инструкции по биомаркерам. Отдельного промпта для этого не завели, текст писался разовым скриптом.
3. **База.** Разрешили новый тип раздела «Организм в целом». Сохранили раздел, удалили 4 раздела по системам, сбросили черновик документа, чтобы он собрался заново.
4. **Состав.** Остались «Общее резюме», «Организм в целом» и «Назначения», причём назначения сгенерировали заново. Распределение показателей по системам в анализе и в справочниках не меняли.
5. **Первая попытка.** Сначала сделали копию анализа. От неё отказались: анализы дублировать нельзя.
6. **Список отчётов.** Отчёты стали группироваться по анализу, а не по дате.

**Правки после генерации:**
- Убрали 2 страницы «Данные пациента».
- Убрали плашку «био возраст / индекс / биомаркеры» на титульнике.
- Такую же плашку убрали в «Общем резюме».
- Поправили титульник: после удаления плашки центр съезжал вниз, теперь имя и заголовок стоят по центру.
- Скрытия хранятся в настройках конкретного отчёта, другие отчёты не меняются. Три флага уже есть в коде: `hidePatientData`, `hideCoverMeta`, `hideOverviewStats`.

**Чего не хватает, чтобы повторять это без ручной работы:** кнопки запуска, отдельного промпта в настройках ИИ, автоматической подстановки скрытий и переключателей в редакторе.

## Как это будет выглядеть

**Для админа или врача, при создании или перегенерации отчёта:**

```text
Тип отчёта:  (•) По системам организма   ( ) Организм в целом
```

- При выборе «Организм в целом» генерация сразу пишет один общий раздел вместо разделов по системам. Затем, как обычно, создаются «Общее резюме» и «Назначения».
- В карточке пациента, в списке его анализов, есть действие «Пересобрать как общий отчёт». Разделы по системам заменяются общим, а анализ и его показатели не трогаются.
- В редакторе отчёта появляется панель «Состав отчёта» с переключателями:
  - страница «Данные пациента»;
  - плашка показателей на титульнике;
  - плашка показателей в «Общем резюме».

  Для общего отчёта все три по умолчанию выключены. Их можно включить обратно для конкретного отчёта.
- В списке отчётов пациента общий отчёт помечен бейджем «Организм в целом».

**Для пациента:** обычный отчёт в разделе «Отчёты», только короче. Состав: титульник без цифр, «Общее резюме», «Организм в целом» (сильные стороны и зоны внимания), «Назначения». PDF собирается так же, как для обычных отчётов.

## Этапы внедрения

1. **Промпт в настройках ИИ.** Новая запись «Общий отчёт — организм в целом». Текст перенесём из того, что сработало у Алёны: порядок разбора, «Сильные стороны» и «Зоны внимания», запрет на разбивку по системам. Логика системных промптов подключается как контекст. В коде промпт не прописываем.
2. **Тип отчёта у анализа.** Анализ помечается как «по системам» или «организм в целом». По умолчанию — «по системам», существующие отчёты не меняются. Отчёт Алёны пометим как общий.
3. **Генерация.** В сборщике отчёта добавим режим «общий»: один вызов ИИ по всем показателям вместо разделов по системам. Дальше резюме и назначения собираются по тем же правилам, в том числе с защитой от противоречий.
4. **Скрытия.** При генерации общего отчёта три флага скрытия ставятся автоматически. Центрирование титульника уже работает.
5. **Интерфейс админки.** Выбор типа в мастере создания и редактирования анализа, действие «Пересобрать как общий отчёт» и панель «Состав отчёта» в редакторе.
6. **Отображение.** Бейдж в списках, проверка веб-версии и PDF на отчёте Алёны и на тестовом пациенте.

## Технические детали

- `ai_prompt_settings`: новый ключ, например `whole_body_report`. Редактируется в админке «Настройки ИИ».
- Тип отчёта хранить в `analyses.cover_overrides.report_kind` (`"systems" | "whole_body"`), рядом с `presentation`. Это сходится с правилом из AGENTS.md и не требует миграции. Альтернатива — отдельная колонка `analyses.report_kind`.
- `report-orchestrator` / `analyze-biomarkers`: ветка `whole_body` пишет одну `recommendations` с `type = 'Организм в целом'`. Этот тип уже разрешён в `validate_recommendation_type()`. Затем идут «Общее резюме» и «Назначения», а при пересборке `report_documents` сбрасывается.
- Рендерер: `resolveDoc` и `getSectionEntries` уже показывают любой тип раздела. Нужна проверка, что «Организм в целом» идёт после резюме и перед назначениями.
- Редактор: переключатели пишут `cover_overrides.presentation` через уже существующее сохранение в `ReportEditorShell`.
- Проверка: отчёт Алёны (анализ `a28ae1ea…`) должен выглядеть так же, как сейчас.
