# Цели Яндекс.Метрики на страницах чекапов

Цель: отслеживать в Метрике (счётчик 109706546) переход к оплате, успешную и неуспешную оплату — отдельно по направлению чекапа и общей целью.

## Какие события и когда

1. Клик «Перейти к оплате» в корзине (до редиректа на Робокассу):
   - `<slug>_payment_click` (например `vitamins_payment_click`)
   - `checkup_payment_click`
2. Возврат с успешной оплатой, когда заказ подтверждён как оплаченный:
   - `<slug>_paid`
   - `checkup_paid`
3. Возврат с неуспешной оплатой (отмена/отказ):
   - `<slug>_payment_failed`
   - `checkup_payment_failed`

Каждая цель отправляется один раз за заказ: успешная — только после подтверждения статуса «оплачено», а не просто по факту возврата на страницу.

## Как узнаём направление на странице возврата

Робокасса возвращает только номер заказа, без названия чекапа. Перед уходом на оплату сохраняем slug чекапа в браузере (привязанный к номеру заказа) и читаем его на странице возврата. Дополнительно страница статуса заказа начнёт отдавать направление заказа — это подстраховка, если хранилище браузера очищено (тогда вместо пары целей уйдёт хотя бы общая).

## Технические детали

- `src/components/landing/energy/EnergyCart.tsx` — в `handlePay` после получения платёжного URL: записать `sessionStorage`/`localStorage` ключ вида `reage:checkup:lastOrder` = `{ invId, slug }` (invId парсим из URL Робокассы), затем `reachGoal` из `src/lib/yandexMetrika.ts` для двух целей, затем редирект.
- `src/pages/EnergyPaymentResult.tsx`:
  - режим `fail` — отправить `<slug>_payment_failed` + `checkup_payment_failed` в `useEffect` один раз;
  - режим `success` — отправить `<slug>_paid` + `checkup_paid` только когда polling вернул `status === "paid"`, с защитой от повторной отправки (ref/флаг в хранилище по invId).
- `supabase/functions/energy-order-status/index.ts` — добавить `bundle` в выборку и в ответ (безопасное поле), использовать как fallback для slug.
- Цели шлём через существующий хелпер `reachGoal(goal)` (`src/lib/yandexMetrika.ts`), а не инлайн-вызовы `ym`.

## Про edge function `energy-create-payment`

Переименование не требуется: функция уже универсальная — принимает `bundle` и обслуживает все чекапы, включая витамины. Имя историческое и видно только внутри кода. Переименование потребовало бы передеплоя и правок ссылок без функциональной пользы, поэтому в этой задаче не делаем.
