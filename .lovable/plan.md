# Партнёр со скидкой 0% — не показывать клиенту

## Что сейчас не так (проверено по коду)

1. **Корзина чекапов сама вписывает код партнёра в поле промокода.** При открытии корзины код из ссылки подставляется в поле всегда, даже когда скидка 0%. Клиент видит чужой код.
2. **Корзина считает промокод применённым при скидке 0%.** Сервер возвращает «партнёр, 0%», а корзина всё равно сохраняет его как применённый промокод и снова вписывает код в поле. Так бывает и у закреплённого клиента, и у клиента по ссылке, и при проверке по телефону/email.
3. **Если клиент сам введёт такой код**, появится «Промокод применён — Скидка 0%».
4. **Что уже работает правильно:** верхняя плашка «Скидка X% от …» и скидка на странице подписки при 0% не показываются.

Закрепление клиента за партнёром и начисление при оплате не трогаем: они работают на сервере и клиенту не видны.

## Что сделаю

- Корзина: код из ссылки вписывается в поле только если скидка больше 0%.
- Корзина: партнёр со скидкой 0% не становится «применённым промокодом», поле не заполняется, сообщений нет. Код из ссылки по-прежнему тихо уходит в оплату, чтобы клиент закрепился за партнёром.
- Ручной ввод кода партнёра со скидкой 0%: пишем «Промокод не найден», как для несуществующего кода.
- Настройка «Не предлагать консультацию врача» при скидке 0% продолжает тихо работать.

## Технически

- `EnergyCart.tsx`: в эффекте открытия `setPromo(ref)` только после ответа с `partner && value > 0`; в `checkPromo` при `partner && value === 0` — `setAppliedPromo(null)`, без `setPromo`, без toast (при ручном вводе — ошибка «Промокод не найден»); `hideConsultation` применять всегда. Ref-код передавать в `energy-create-payment` отдельно (как в подписке через `getRefCode()`), если в поле пусто.
- Проверить, что `energy-create-payment` принимает код при пустом промокоде (сейчас берёт из поля) — при необходимости добавить поле `refCode`.
