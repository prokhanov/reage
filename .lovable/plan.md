# Вернуть кнопку «Перегенерировать» в просмотре пациента

## Что происходит

Кнопка «Перегенерировать» (и «Редактировать анализ») на странице анализа показывается только при выполнении двух условий одновременно: режим просмотра пациента включён И отдельная повторная проверка прав доступа прошла успешно (`src/pages/AnalysisDetail.tsx`, условие `hasPatientAccess && isViewMode`).

Окно «Просмотр пациента» само по себе могут открыть только сотрудники — страница «Пациенты» в админке уже защищена проверкой доступа. То есть внутри этого окна вторая проверка избыточна: она выполняется заново, асинхронно, и при любом сбое (ошибка запроса прав, таймаут, гонка при открытии окна) молча возвращает «нет доступа» — и кнопки просто не рисуются. Именно это видно на скриншоте: шапка анализа есть, кнопок справа нет.

## Что делаем

1. В `src/pages/AnalysisDetail.tsx` упрощаем условие показа админских кнопок: вместо `hasPatientAccess && isViewMode` — только `isViewMode`. Режим просмотра пациента технически может включить только сотрудник из админки (контекст `ViewAsPatientProvider` используется только в окне просмотра из раздела «Пациенты»), поэтому безопасность не страдает, а лишняя хрупкая проверка убирается.
2. Проверяем, что у обычного пациента в его кабинете кнопки по-прежнему не появляются (у пациента `isViewMode` всегда выключен).
3. Прогоняем сборку и проверяем в превью: открываем «Пациенты» → «Просмотр» → анализ — кнопки «Редактировать анализ» и «Перегенерировать» (со стрелкой выбора «По системам» / «Организм в целом») на месте справа вверху.

## Технические детали

- Меняется одна строка-условие в шапке `AnalysisDetail.tsx` (строка ~833).
- Хук `usePatientModuleAccess` остаётся для других мест, где он реально нужен; здесь его результат больше не используется.
- Логика самой перегенерации (`handleAnalyze`, выбор режима, подтверждение) не трогается.
