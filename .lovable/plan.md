# Описания показателей в примере расшифровки — из базы

Сейчас пояснения к показателям в окне «Пример расшифровки» написаны отдельно и не совпадают с текстами настоящих отчётов ReAge. В базе у каждого показателя уже есть готовое пояснение, которое используется при подготовке отчёта. Берём его.

## Что изменится

- Образовательный абзац в карточке показателя берётся из базы — тот же текст, что в больших отчётах.
- Диапазоны (норма, оптимум, критические значения), название и единицы тоже берутся из базы, чтобы шкала в примере совпадала с настоящей.
- Строка результата («Ваш показатель X находится …») и блок «Что это значит для вас» при отклонении остаются как сейчас — они зависят от конкретного значения в примере.
- Пока пояснения загружаются, в окне показывается короткий индикатор загрузки; если загрузка не удалась, показывается запасной текст, который уже есть в файле примера.

## Показатели без пояснения в базе

Для шести показателей записи в базе нет: эстрадиол, ЛГ, ФСГ, пролактин, свободный тестостерон (расчётный), FIB-4. Для них остаётся текущий текст из файла примера. Отдельно отмечу: женские циклозависимые гормоны на платформе исключены — они есть только в чекапе «ReAge Женские гормоны» как товарная позиция.

## Техническая часть

- Новый хук (например `src/hooks/useReportBiomarkers.ts`) читает `biomarkers` (`code, name, unit, general_description, description`, все поля диапазонов) через клиент Lovable Cloud, с модульным кэшем — по образцу `src/hooks/useBiomarkerNames.ts`. Таблица доступна для чтения анониму (политика «Anyone can view biomarkers»), логин не нужен.
- В `CheckupExampleReport.tsx` маппер `toReportBiomarker` сначала ищет запись по коду в загруженной карте и берёт из неё имя, единицы и все `normal_/optimal_/critical_` поля (включая гендерные); при отсутствии — падает на inline-данные из `src/data/checkupExampleReports.ts`.
- `buildCommentary` использует `general_description ?? description ?? marker.meaning` как первый абзац; остальная сборка (строка результата через `RESULT_PHRASE`, блок «Что это значит для вас» из `marker.feeling`) не меняется.
- Коды в примере сверены с базой: совпадают все, кроме `E2`, `LH`, `FSH`, `PRL`, `FTEST`, `FIB-4`.
- Файл `src/data/checkupExampleReports.ts` не переписываем — он остаётся источником значений, сценарных отклонений и запасных текстов.
