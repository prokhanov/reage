# Партнёрская программа: доделать и проверить со всех сторон

## 1. Скидка партнёра на странице подписки (то, что вы попросили)
- При открытии страницы подписки сайт спрашивает у сервера, есть ли у клиента партнёр: закреплённый за аккаунтом, телефоном или email, либо код из партнёрской ссылки, сохранённый в браузере.
- Если партнёр есть, у каждого тарифа видна зачёркнутая старая цена, новая цена и строка «Скидка N% по промокоду КОД». Поле промокода уже заполнено этим кодом.
- Код из ссылки уходит в оплату автоматически. Сейчас клиент, пришедший по ссылке, но ещё не закреплённый, скидку на подписку не получает, потому что код не передаётся. Исправляем.
- Если клиент закреплён за партнёром и вводит чужой или обычный промокод, для него ничего не меняется: остаётся скидка его партнёра, промокоды не складываются.
- Если у партнёра скидка 0%, клиенту ничего не показываем.

## 2. Найденные дыры, которые закрываю
- **Приватность.** Сейчас проверка на сайте открыта всем, и по чужому телефону или email можно узнать, закреплён ли человек за партнёром и как этого партнёра зовут. Сделаю так: без входа проверяется только код из ссылки. Проверка по телефону и email идёт только в корзине и возвращает лишь размер скидки, без имени партнёра.
- **Доступ к админке «Партнёры».** Сейчас раздел видит только главный администратор. Открою его обычным администраторам, у которых есть доступ к промокодам, и проверю, что база отдаёт им данные.
- **Режим «от лица пациента».** Администратор, который смотрит кабинет пациента, не должен видеть пункт «Партнёрам» и не должен получать скидку этого пациента.
- **Плашка скидки.** Показывается только гостям и незакреплённым клиентам со ссылкой, а также клиентам своего партнёра. Партнёр у себя плашку не видит.

## 3. Полная проверка по ролям

```text
Гость:        ссылка /r/КОД -> плашка -> корзина с кодом -> оплата -> закрепление по телефону/email
Гость:        вторая ссылка другого партнёра до оплаты -> побеждает последняя
Клиент:       закреплён -> чужая ссылка/код -> цены и скидка прежние
Клиент:       вход с нового устройства -> скидка по аккаунту/телефону сохраняется
Клиент:       подписка -> скидка видна заранее -> в оплате та же сумма
Обычный юзер: нет пункта меню, /partner = «не найдено», нигде нет упоминания партнёров
Партнёр:      код, ползунок 0-20%, «без консультации», заказы без имён, начисления
Админ:        включить/отключить партнёра, начисления за месяц, «Выплачено», перезакрепление
```
- Проверяю в браузере и запросами к базе на тестовых аккаунтах. Живые оплаты не провожу: оплату имитирую прямо в базе, чтобы проверить закрепление и начисления, а тестовые данные потом удаляю.
- Отключённый партнёр: его ссылки и коды перестают давать скидку, но клиенты за ним остаются.

## Что остаётся на потом (по вашим решениям)
Возвраты, самореферал, юридическая часть, Метрика, выплаты через систему (сейчас вручную), вход партнёра по SMS.

## Технические детали
- Для подписки на странице: вызов `partner_offer(getRefCode())` и расчёт через `applyPartnerDiscount`. В `robokassa-create-payment` передавать `promoCode || getRefCode()`.
- Миграция: `partner_offer` для anon принимает только код, без контактов, и не возвращает `name`. `checkup_promo_preview` не возвращает `name`.
- Раздел `/admin/partners` перевести на проверку модуля `promo_codes`, пункт меню — на тот же модуль. Проверить RLS таблиц `partners`, `partner_codes`, `partner_clients`, `partner_payouts`, выданные права (GRANT) и то, что `has_admin_permission` подходит для роли admin.
- `usePartnerMe` отключать в режиме «от лица пациента». Предложение партнёра при оплате подписки считается только по реальному пользователю.
- После правок заново задеплоить `robokassa-create-payment` и прогнать сборку.
