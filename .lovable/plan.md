# Стратегия здоровья: только чтение из БД у пациента

## Как должно быть

Стратегию генерирует **только админ по клику**. Результат сохраняется в БД и с этого момента является единственным источником. Пациент при заходе просто читает сохранённый снапшот — никаких вычислений и вызовов ИИ с его стороны.

## Что сейчас не так (это и есть причина долгой загрузки)

1. `src/pages/HealthStrategy.tsx` при заходе пациента ищет «подходящий» снапшот и, если он не проходит проверки, **сам вызывает `compute-health-strategy`** и ждёт ответ ИИ (`await generate(false)`), держа страницу в скелетоне. По логам шлюза такой вызов длится 19–42 секунды.
2. Отбраковка снапшота происходит часто и без реальной необходимости — снапшот считается «протухшим», если:
   - он создан раньше `report_documents.published_at` (любая перепубликация отчёта врачом обнуляет уже посчитанную админом стратегию);
   - его Health Index не совпадает с текущим значением анализа;
   - в нём пустые `roadmap` / `key_biomarkers` / `expectations` либо роадмап старого формата.

   По данным БД: у `a.s.prokhanov@yandex.ru` снапшот от 23.07 против публикации отчёта 07.08, у `svetlanamineeva88@gmail.com` — 10.07 против 07.08. Оба при заходе пациента запускают полную генерацию заново.
3. Те же проверки продублированы на сервере в `compute-health-strategy` (условия кеша, строки ~220–237) — то есть даже принудительный вызов не отдаёт сохранённое, а считает заново.

## Что сделать

**1. Убрать любую генерацию со стороны пациента.**
В `HealthStrategy.tsx` полностью удалить ветку `await generate(false)`. Страница только читает последний снапшот пациента из `health_strategy_snapshots` и рендерит его как есть. Кнопка «Пересчитать» остаётся исключительно для сотрудника (условие `canRecalculate` уже есть).

**2. Убрать проверки «свежести» при чтении.**
Показываем последний сохранённый снапшот пользователя без сверки с `published_at`, без сверки Health Index и без требований к заполненности `roadmap`/`expectations`. Что админ сохранил — то пациент и видит.

**3. Состояние «стратегии ещё нет».**
Если снапшота нет вовсе — вместо генерации показываем спокойную заглушку: «Стратегия готовится врачом» (без спиннера и без ожидания).

**4. Серверная функция — только по явной команде админа.**
`compute-health-strategy` вызывается только с `preview`/`publish`/`force` из админского интерфейса. Ветку «отдать/пересчитать кеш при обычном вызове» и её условия убрать, чтобы никакой автозапуск был невозможен.

**5. Ускорить само чтение страницы (побочный выигрыш, секунды).**
Сейчас на странице 4 последовательные волны запросов, самая тяжёлая тянет два анализа со всеми `analysis_values` и 20+ колонками справочника биомаркеров, плюс отдельный дублирующий запрос «все анализы». Объединить в одну параллельную волну и урезать выборку.

## Технические детали

- `src/pages/HealthStrategy.tsx`: `load()` — убрать `generate(false)` и фильтры `matched`; читать `health_strategy_snapshots` (последний по `created_at`), снимать `loading` сразу после чтения.
- `supabase/functions/compute-health-strategy/index.ts`: блок кеш-валидации ~220–237 (`cacheNewerThanPublication`, `cacheMatchesLatestHealthModel`, `hasLegacyRoadmap`) — не нужен, если функция вызывается только по кнопке админа.
- Админский путь (`src/pages/Dashboard.tsx`: `runRecompute` / `publishStrategy`) не меняется.

Итог: у пациента страница откроется за время обычного запроса к БД, без ожидания ИИ.
