# Рекламные баннеры в персональном отчёте разового чекапа

## Результат

Сотрудник сможет выбрать один или несколько чекапов в редакторе персонального отчёта. После сохранения для каждого выбранного чекапа появится отдельный баннер в конце отчёта и PDF с персональным промокодом, QR-кодом и ссылкой на оформление.

## Согласованные правила

- Если отчёт сделан по полному чекапу, засчитывается его фактически оплаченная стоимость: итоговая цена = `(цена рекламируемого чекапа − фактически оплаченная цена полного чекапа) × 0,9`, с округлением до рублей.
- Если отчёт сделан по обычному чекапу, его стоимость не вычитается: на рекламируемый чекап даётся ровно 10% скидки.
- Для полного исходного чекапа рекламируемый чекап не показывается, если он не дороже фактически оплаченной суммы.
- Код действует только для владельца отчёта, только на указанный чекап и только один раз.
- Без активного входа ссылка сохраняет выбранный чекап и код, но просит владельца войти перед применением скидки.
- Реальный срок действия — 30 дней; на баннере показывается дата создания + 14 дней.
- Скидки не складываются: для подходящей позиции применяется наиболее выгодная из баннерной, партнёрской, обычного промокода или допродажи.
- Баннерная скидка относится к одному экземпляру рекламируемого чекапа; другие товары корзины рассчитываются отдельно.
- Снятие галочки деактивирует неиспользованный код. Повторный выбор создаёт новый код и новый 30-дневный срок.
- Снятие отчёта с публикации временно скрывает баннеры, но не аннулирует их; удаление баннера или отчёта деактивирует неиспользованные коды.

## Что будет сделано

1. **Надёжная цена исходного чекапа**
   - Определять, относится ли связанный с анализом заказ к полному чекапу или к обычному.
   - Для полного чекапа сохранять фактически оплаченную сумму по позиции, а не делить общую сумму заказа поровну; для обычного чекапа исходная сумма в расчёте не участвует.
   - Для старого полного чекапа использовать безопасный резервный расчёт; если точную цену восстановить нельзя, не разрешать создание баннера и показать сотруднику понятную причину. Для обычного чекапа это ограничение не требуется.

2. **Отдельные персональные предложения**
   - Добавить защищённые записи предложений с привязкой к отчёту, пациенту, типу исходного чекапа, рекламируемому чекапу, применённому правилу расчёта, фиксированной скидке, срокам и состоянию использования.
   - Генерировать код только при нажатии «Сохранить» в окне «Баннеры».
   - Не раскрывать список кодов и владельцев посетителям сайта.

3. **Выбор баннеров сотрудником**
   - Добавить в редактор отчёта кнопку «Баннеры» и окно со списком доступных чекапов, рассчитанной ценой и галочками.
   - Исключить уже купленные пациентом чекапы; для отчёта по полному чекапу также исключить варианты с нулевой или отрицательной расчётной ценой.
   - Сохранять изменения атомарно: новые предложения создавать, снятые — деактивировать, уже выбранные — не пересоздавать.

4. **Баннер в отчёте и PDF**
   - Собрать баннер по приложенному макету средствами интерфейса: название, разбивка цены, код, фиксированная скидка, дата, QR и кнопка.
   - Добавить баннеры последними страницами после рекомендаций; один баннер — одна неделимая страница.
   - Использовать один и тот же источник данных для просмотра сотрудником, кабинета пациента и серверного PDF, чтобы версии не расходились.
   - Включить предложения в версию опубликованного отчёта и обновлять PDF при изменении баннеров.

5. **Ссылка, QR и вход**
   - Ссылка открывает страницу нужного чекапа, кладёт в корзину только выбранную позицию и переносит персональный код.
   - Если пациент не вошёл, показать вход и после него восстановить оформление без потери выбранного товара.
   - После входа сервер проверяет владельца отчёта; другой пользователь не получает скидку.

6. **Корзина и оплата**
   - Рассчитывать все доступные скидки по каждой позиции и выбирать максимальную, не суммируя их.
   - Повторно проверять владельца, товар, срок, статус и сумму на сервере перед созданием платежа.
   - Записывать в заказ идентификатор предложения и фактическую скидку, чтобы аудит не зависел от текста кода.
   - При подтверждённой оплате погашать код атомарно и не допускать двойного использования при параллельных платежах.

7. **Удаление и приватность**
   - При удалении отчёта или анализа деактивировать все его неиспользованные предложения.
   - Удалять связанный PDF из закрытого хранилища; сейчас запись отчёта удаляется, но физический PDF может остаться.
   - Использованные предложения сохранять в истории для сверки оплаты, но больше не принимать.

8. **Проверка перед завершением**
   - Отдельно проверить оба расчёта: зачёт фактической оплаты полного чекапа и ровно 10% после обычного чекапа; затем проверить корзину с несколькими товарами, партнёрскую скидку и допродажу.
   - Проверить чужой аккаунт, выход из аккаунта, истёкший/снятый/использованный код и два параллельных платежа.
   - Проверить экранный отчёт и PDF на компьютере и телефоне, включая QR-код и перенос баннера между страницами.
   - Не запускать генерацию отчёта на живом анализе Алёны; для проверки использовать безопасные тестовые данные.

## Технические детали

- Новая сущность предложений будет отдельной от обычных промокодов подписок и партнёрских кодов: их текущая модель не умеет безопасно связывать код с отчётом, владельцем и конкретным чекапом.
- Все проверки скидки и погашение выполняются на сервере; параметры ссылки и данные браузера не считаются доверенными.
- Изменение состава баннеров должно менять снимок опубликованного отчёта и его контрольную сумму, чтобы PDF действительно перегенерировался.
- Изменения `/landing-v2`, Callibri и запуск генерации медицинского отчёта в эту работу не входят.
