# Промокод: выбор тарифов и чекапов

## Что увидит админ
В окне «Создать / Редактировать промокод» блок «Область действия» заменяется на два понятных раздела-переключателя:

```text
Где действует промокод
[x] Годовые тарифы     ( ) Все тарифы   ( ) Выбранные  -> чипы тарифов
[x] Разовые чекапы     ( ) Все чекапы   ( ) Выбранные  -> чипы чекапов (+ поиск, «Выбрать все / Снять»)
```
- Чекапы берутся из админки (те же 12 активных + «Полный чекап»), с ценой рядом.
- Нельзя сохранить, если не выбран ни один раздел или выбрано «Выбранные» без единого пункта.
- В списке промокодов колонка «Где действует» показывает: «Все тарифы», «Тарифы: Старт, …», «Все чекапы», «Чекапы: Щитовидка, …» или оба.
- То же — в окне массовой генерации партии.

## Подводные камни, которые закрываем
1. **Сейчас любой код с выбранными тарифами отклоняется на чекапах** («не действует на чекапы») — для чекапов проверка становится своей, независимой от тарифов.
2. **Скидка на корзину из нескольких чекапов**: если код только на «Щитовидку», скидка считается только от её цены, а не от всей корзины. Фиксированная сумма — не больше суммы подходящих чекапов. Распределение скидки по позициям заказа — только на подходящие.
3. **Корзина без подходящих чекапов** — понятная ошибка «Промокод действует только на: …».
4. **«Бесплатные месяцы»** имеют смысл только для тарифов — при включённых чекапах этот тип недоступен (и наоборот подсказка).
5. **Консультация и выезд медсестры** скидкой не затрагиваются (как сейчас).
6. **Не складывается** с партнёрской скидкой, скидкой допродажи и баннером из отчёта — выигрывает большая, как сейчас.
7. **Старые коды не ломаются**: «Все» остаётся «все тарифы + все чекапы», «Чекапы» — «все чекапы», «Подписки» — только тарифы.
8. **Чекап выключен или переименован** — код просто перестаёт на него действовать; в админке такой пункт помечается «неактивен».
9. **«Один раз на пользователя» и лимит** считаются одинаково для тарифов и чекапов (общий счётчик).
10. Окно на телефоне — прокрутка внутри, чипы переносятся.

## Технические детали
- Миграция: таблица `promo_code_checkups (promo_code_id → promo_codes ON DELETE CASCADE, checkup_slug text, unique)` + GRANT (authenticated select, service_role all) + RLS (чтение/запись — staff с правом promo_codes).
- `promo_codes`: добавить `checkups_applies_to text default 'all'` ('all' | 'specific'); существующее поле `scope` ('all' | 'subscriptions' | 'checkups') определяет разделы.
- `checkup_promo_preview`: убрать запрет `applies_to <> 'all_plans'`; вернуть `allowed_checkups` (массив slug или null = все). Новый параметр `p_slugs text[]` для проверки корзины.
- `apply_promo_code`: отклонять коды со `scope = 'checkups'` (проверить текущую логику, оставить как есть, если уже так).
- `energy-create-payment`: считать базу скидки по подходящим позициям, распределять `discountShares` только на них.
- Корзина на сайте: показывать скидку только по подходящим чекапам, текст «Действует на: …».
- Форма: `PromoCodeFormDialog`, `GeneratePromoBatchDialog`, `usePromoCodes` (сохранение ссылок), `generate-promo-codes` (вставка `promo_code_checkups`), колонка в `PromoCodes.tsx`.
- Проверка: тестовые коды (все чекапы / один чекап / только тарифы) — расчёт в корзине из 1 и 2 чекапов, и на странице подписки.
