# Вернуть свой пример отчёта каждому чекапу

## Что произошло

Индивидуальные примеры никуда не пропали — они по-прежнему лежат в коде для чекапов: Энергия, Щитовидная железа, Железо, Метаболизм, Печень, Почки, Базовый, Витамины и минералы, Волосы.

Но функция, которая выбирает пример для страницы, сейчас игнорирует, какой именно чекап открыт, и всегда возвращает один общий демонстрационный пример (ферритин, витамин D, гемоглобин). Поэтому под всеми кнопками «Посмотреть пример расшифровки» показывается одно и то же.

Похоже, общий пример появился как временная заглушка в момент, когда добавлялись чекапы без собственных примеров — Сердце и сосуды, Женские гормоны, Мужские гормоны. Заглушку включили для всех страниц сразу и не вернули обратно.

## Что сделаем

1. Вернуть выбор примера по конкретному чекапу: открыт «Печень» — показывается печёночная панель, открыт «Железо» — железная.
2. Дописать три недостающих примера в том же формате, что и остальные:
   - Сердце и сосуды (липиды, ApoB, Lp(a), hs-CRP)
   - Женские гормоны
   - Мужские гормоны
3. Проверить каждую из 12 страниц: набор показателей в примере совпадает с составом именно этого чекапа, резюме и рекомендации соответствуют картине.

Формат самого отчёта не меняется: то же введение, карточки показателей со шкалой ReAge, «что это значит» и «как это может ощущаться», рекомендации, дисклеймер.

## Технические детали

- `src/data/checkupExampleReports.ts`: `getCheckupExampleReport(slug)` сейчас всегда возвращает `UNIVERSAL_EXAMPLE_REPORT`. Восстановить поиск по `CHECKUP_EXAMPLE_REPORTS[slug]` с fallback на универсальный только если примера нет.
- Добавить записи `cardio-risk`, `female-hormones`, `male-hormones` в `CHECKUP_EXAMPLE_REPORTS`, при необходимости расширить справочник `REF` недостающими биомаркерами.
- Сверить коды маркеров каждого примера с составом чекапа из `src/data/checkups.ts`.
